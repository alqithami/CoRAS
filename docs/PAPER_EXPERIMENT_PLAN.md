# CoRAS Paper Experiment Plan

## Main eight-page paper

Use the minimum high-signal results:

1. One method table at alpha = 0.10 from the controlled sim-to-shift track.
2. One method table at alpha = 0.10 from the DROID_100 offline real-robot track.
3. One per-domain coverage plot showing camera/lighting/occlusion or held-out task domains.
4. One qualitative prediction-set figure: small set, large set, and false-singleton failure.
5. A limitations paragraph stating that no new robot rollouts were collected.

## Appendix

Include all sweeps generated by the scripts:

- Seeds: 0--4.
- Alpha: 0.05, 0.10, 0.20.
- Calibration fraction: 0.10, 0.25, 0.40.
- Optional codebook sizes: 32, 64, 128.
- Per-domain tables for all methods.
- Failure cases from prediction-set CSVs.
- Train/tune/calibration/test split details.
- Runtime/hardware details.

## Reviewer questions directly covered

**Is this just ordinary conformal prediction?**  
No. The comparisons include vanilla conformal, APS, temperature+conformal, and prompt-only; CoRAS isolates the prompt-adapted conformal layer.

**Does it work under domain shift?**  
The controlled track uses explicit camera/lighting/occlusion shifts. DROID_100 uses held-out task domains.

**Does it need new robots?**  
No. The DROID_100 track uses public robot data. The controlled track is self-contained.

**Are tune and calibration splits separated?**  
Yes. The scripts use tune for prompt/temperature tuning, calibration for conformal thresholds, and test for final metrics.

**Are repeated seeds and calibration-size effects reported?**  
Yes. `run_experiment_matrix.py` and `aggregate_results.py` generate these tables directly.
